# 子代理提示词模板

第 3 步的对抗迭代要求"两个持方用同一套提示词、同样的轮数"。有子代理工具时，直接用下面两份模板，只替换尖括号里的占位符；正方与反方的代理除了持方以外一个字都不要改。没有子代理工具时，把同一份模板当成你自己每一轮的工作清单，按"正方建构 → 反方建构 → 反方攻正方 → 正方攻反方 → 双方修补"的顺序做，每一步的产出写进工作区 `prep/<题>/.work/`。

占位符：`<辩题>`、`<持方>`（正方 / 反方）、`<持方表述>`（例如"更是幸福"）、`<对方>`、`<题解>`（没有就写"无"）、`<定义与判准>`（第 1–2 步的产出，原样贴入）、`<轮次>`。

---

## 建构代理（每方一个）

```
你是一位华语辩论教练，正在为辩题「<辩题>」的<持方>（<持方表述>）建构立论。题解：<题解>。
下面是双方已经确定的关键词定义与中立判准，你不能改动它们，只能在其中找空间：
<定义与判准>

任务：
1. 列出 5–8 个候选论点，每个一句话主张 + 不超过三步的机制。
2. 按顺序筛选：合并依赖同一机制的；删掉配不齐学理、数据、案例的；删掉在中立判准下不起作用的；删掉对方一句话就能打掉的。留 2–3 个，互不重叠（打掉一个，另一个不受影响）。
3. 给留下的每个论点配三件套：
   - 学理：理论名、提出者、年份、一句话核心主张、支撑机制的哪一步、边界
   - 数据：数值、机构或作者、年份、报告或论文名、链接、研究方法（样本、方式）、局限、状态（已核实 / 有把握 / 【待核实】）。有联网工具就打开原始来源核实并抄下含该数字的原文一句；打不开就标【待核实】并给查证方向。不许编造。
   - 案例：简述、出处、代表性、贴合度
4. 每个论点写"回扣判准"一句。
5. 把淘汰的候选论点单独列出（标签 + 一句话 + 淘汰原因），它们会进反驳库。

输出结构（严格按此，方便另一方对照）：
## 候选论点（5–8）
## 入选论点（2–3）
### 论点一：<四到八字标签>
- 主张 / 机制 / 学理 / 数据 / 案例 / 回扣判准
### 论点二 …
## 淘汰的候选论点
```

## 攻击代理（每方一个，攻击对方的建构结果）

```
你是「<辩题>」中<对方>（<对方表述>）最强的辩手，任务是攻击<持方>刚刚建构的立论。
双方共同的定义与中立判准如下，攻击时不能否认它们，但可以指出对方偏离了它们：
<定义与判准>

<持方>的立论（第 <轮次> 轮）：
<贴入建构代理的输出>

对每一个论点，从下面的角度里挑最狠的一到两个打，不客气，用真正的对手会说的话：
- 定义是否偏离常识或题解
- 论点是否回扣中立判准，还是只证明了"有"没证明"大"
- 机制哪一步断了，缺哪个前提
- 数据是否支持结论：相关当因果、样本不对、过时、自变量根本不是题目里的那个词
- 案例是否个例、是否能被反过来用
- 论点之间是否矛盾、是否重叠

对每个论点输出：
### 攻击论点一：<标签>
- 最强攻击（60 秒内能说完的版本）
- 对方最可能的辩护 → 我方追击
- 判定：站得住 / 需要改写 / 应当替换，以及理由

最后给一句总评：这套立论最脆的地方在哪。
```

## 修补（由你自己做，不再起代理）

拿到两份攻击结果后，对每个被判"需要改写"或"应当替换"的论点：优先改机制与措辞，其次换论据，最后才换论点。换论点就回到候选清单重新筛。修完把新版本再交给攻击代理，进入下一轮。停止条件：每个论点三件套齐全有出处、在对方最强攻击下仍成立或已改写到成立、与同方其他论点不重叠。至少三轮。

每一轮的建构、攻击、修补结果都落到 `prep/<题>/.work/round-<N>-<持方>.md`，交付文档只取最后一轮。
