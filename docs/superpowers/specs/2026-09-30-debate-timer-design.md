# 华语辩论计时器 设计文档

日期：2026-09-30　分支：`feature/debate-timer`

## 0. 目标与约束

**要做什么**：一个华语辩论计时器，内置本仓库赛制库（`.claude/skills/debate-prep/references/formats/*.md`）里的全部赛制，正式比赛投影与队内模辩都用它。

**用户明确要求的**

- 视觉美观、有设计感、用动画
- 可移植，面向 Windows
- 界面里就能编辑赛制、加环节，能导入导出文件
- 单屏镜像与双窗口（操作台 + 投影页）都支持
- 以后可以给不同赛制接入不同的背景设计（主题）

**由此定下的约束**

- 交付物是**一个** HTML 文件 `timer/debate-timer.html`：双击用 Edge 打开，离线可用，零依赖，拷到 U 盘就能带走
- 不用任何 CDN、外链字体、npm 包。本机没有 Node，构建与测试只用 Python 3 和系统自带的 Edge（或 Chrome）
- `file://` 下 Chromium 不允许 ES module 和 `fetch` 本地文件，所以源码是经典脚本（classic script），共享一个全局命名空间 `window.DT`，构建时按固定顺序内联
- 计时员可能不装任何东西、不会写代码

**调研结论**（用于定默认值，出处见对话记录）

- 普遍惯例只有两个铃点：剩 30 秒一声短铃，时间到终止铃（两三声）。5 秒 / 3 秒逐秒提示只是个别软件的做法，所以做成可选、默认关
- 规则里没有统一的超时处理，惯例是辩手必须停下、评委酌情扣分。所以单方环节超时后显示超出的时间（+0:07），不强行打断
- 自由辩与对辩：双方各自计时，一方落座即切到对方；一方用完后自动锁定，另一方继续说到用完，也可以放弃剩余时间
- 键位没有行业标准。常见：空格切换或开始暂停、方向键换环节、左手 A 键管左侧（正方）、右手 L 键管右侧（反方）
- 计时员最常见的失误是自由辩切换按错，所以要有撤销，并且切换键按持方而不是只有"切换"
- 现有开源单文件工具要么赛制写死，要么一个赛制一个文件。本计时器的差异点：赛制可编辑、跟赛制库同源、双窗口、铃声精确到毫秒

## 2. 数据模型

### 2.1 赛制（Format）

```json
{
  "id": "ustc-freshman-cup",
  "name": "中科大新生辩论赛",
  "builtin": true,
  "source": "ustc-freshman-cup.md",
  "theme": "hall",
  "bells": { "warn": [30], "countdown": 0, "end": "double" },
  "stages": [
    { "id": "ustc-freshman-cup-1", "name": "正方一辩开篇立论", "type": "single", "side": "pro",
      "secs": 180, "speaker": "正一", "block": "A", "note": "" },
    { "id": "ustc-freshman-cup-2", "name": "反方四辩质询正方一辩", "type": "single", "side": "con",
      "secs": 120, "speaker": "反四 问，正一 答", "block": "A", "note": "双边计时：问答共用这一个表" },
    { "id": "ustc-freshman-cup-5", "name": "评委打分", "type": "break", "side": null, "secs": 30 },
    { "id": "ustc-freshman-cup-15", "name": "自由辩论", "type": "dual", "side": null, "secs": 240,
      "first": "pro", "speaker": "全员", "block": "D", "note": "A 给正方、L 给反方；一方用完自动转给对方" }
  ],
  "extras": []
}
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 内置赛制用赛制文件名（去掉 `.md`）；用户赛制用 `u-` + 随机串 |
| `name` | string | 显示名，必填，≤ 40 字 |
| `builtin` | bool | 内置赛制为 true；用户改过的内置赛制仍为 true（可恢复默认） |
| `source` | string? | 内置赛制的来源文件名 |
| `theme` | string | 主题 id，未知的 id 退回 `hall` |
| `bells` | Bells | 赛制默认铃声 |
| `stages` | Stage[] | 至少 1 个 |
| `extras` | ExtraGroup[] | 可插入环节组，可为空 |

**Stage**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 在赛制内唯一 |
| `name` | string | 必填，≤ 40 字 |
| `type` | `"single"` \| `"dual"` \| `"break"` | 见 2.3 |
| `side` | `"pro"` \| `"con"` \| `null` | `single` 必填（色场归属，质询 / 盘问填提问方）；`dual`、`break` 为 null |
| `secs` | int | 1–3600；`dual` 是**每方**的秒数 |
| `first` | `"pro"` \| `"con"` | 仅 `dual`，空格首次开始时先给谁，默认 `pro` |
| `speaker` | string? | 投影上显示的发言人一行 |
| `block` | string? | 打分块 / 段，用于投影底部进度条分组 |
| `note` | string? | 只给计时员看的提示，显示在操作台，不上投影 |
| `bells` | Partial&lt;Bells&gt;? | 覆盖赛制默认铃声 |

**Bells**

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `warn` | int[] | `[30]` | 提示铃点（剩余秒数），每个响一声 `ding`；可以多个，如 `[60, 30]` |
| `countdown` | int | `0` | 最后 N 秒每秒一声 `tick`（N ≤ 10）；0 为关。用户说的 5 秒、3 秒在这里开 |
| `end` | `"double"` \| `"triple"` \| `"long"` \| `"none"` | `"double"` | 终止铃 |

`break` 环节的有效铃声固定为 `{warn: [], countdown: 0, end: "chime"}`，不受赛制默认值影响，但可以用环节自己的 `bells` 覆盖。

有效铃声 = 内置默认 ← 赛制 `bells` ← 环节 `bells`，逐字段覆盖。`DT.store.effectiveBells(format, stage)` 负责合并。

**ExtraGroup**（奇袭这类"任意环节结束后可插入、每方限次"的环节）

```json
{ "group": "奇袭", "perSide": 1, "variants": [
  { "name": "奇袭质询", "type": "single", "secs": 150, "note": "双边计时" },
  { "name": "奇袭申论", "type": "single", "secs": 120 } ] }
```

插入时由计时员选持方和形式，`side` 在插入时填上，名字显示为「正方奇袭质询」这类。`perSide` 是整组的次数上限（两种形式合计）。

### 2.2 场次（Session）

开赛时由赛制和开赛页信息生成，存在 `localStorage['dt.session.v1']`，每次动作后保存，意外关闭后可以恢复。

```js
{
  schema: 1,
  id: 's-…',
  createdAt: epochMs,
  match: { title: '新生赛 第 3 场', proMotion: '…', conMotion: '…',
           proTeam: '物理学院', conTeam: '化学院', proSeat: 'left' },  // proSeat: 'left'|'right'
  format: { …赛制的深拷贝… },     // 开赛后改赛制不影响正在打的比赛
  theme: 'hall',
  timeline: [Stage…],              // format.stages 的拷贝，插入的奇袭拼进这里；插入的环节带 extra: true
  cursor: -1,                      // -1 = 开场卡；timeline.length = 结束卡
  runs: { [stageId]: Run },        // 懒创建
  extrasUsed: { '奇袭': { pro: 0, con: 0 } },
  history: [ …快照… ],             // 撤销栈，最多 100 条，不持久化也行（持久化时截到 20 条）
}
```

**Run**（一个环节的运行状态）

```js
{
  kind: 'single'|'dual'|'break',
  clocks: { main: Clock } | { pro: Clock, con: Clock },
  active: 'main'|'pro'|'con'|null,   // dual 未开始时为 null
  running: false,
  since: null,                        // 当前这段运行开始的 epochMs
  locked: { pro: false, con: false }, // 用完或放弃（仅 dual）
  yielded: { pro: 0, con: 0 },        // 放弃的毫秒数（本场记录用）
  fired: { main: [], pro: [], con: [] }, // 已触发的铃点 key，如 'w30'、'c5'、'end'
  done: false                         // 环节完成（dual 双方都锁定、break 到 0）
}
Clock = { total: ms, used: ms }       // used 只在暂停/切换/锁定时结算
```

`remaining(run, clockId, now) = total - used - (running && active === clockId ? now - since : 0)`，毫秒，可为负（单方超时）。

### 2.3 三种计时类型

赛制库「计时」一列到类型的映射（`build.py` 做同样的映射）：

| 赛制库写法 | 类型 | 计时员操作 |
|---|---|---|
| 单方 | `single` | 空格开始 / 暂停 |
| 双边计时（质询） | `single`，`side` = 提问方 | 同上；问答共用一个表 |
| 单边计时，时长不带「各」（盘问） | `single`，`side` = 盘问方 | 同上；对方回答时按 P 暂停（note 里写明） |
| 单边计时 / 各自计时，时长带「各」（对辩、自由辩） | `dual` | A / L 把发言权给正方 / 反方，空格在双方之间切换 |
| —（评委打分、中场休息） | `break` | 空格开始 / 暂停；到 0 自动停 |

## 3. 计时引擎（engine.js）

纯函数：每个动作 `(session, now) → session`，不修改入参（返回新对象，结构共享可以，但不能就地改）。`now` 是毫秒时间戳，由调用方传入；浏览器里用 `performance.timeOrigin + performance.now()`（两个窗口可比）。

### 3.1 公共 API

```js
DT.engine = {
  createSession(format, match, now, opts?) → session      // cursor = -1（开场卡）
  currentStage(session) → Stage | null
  getRun(session, stageId?) → Run                          // 没有就按 stage 新建（不写回）
  remaining(run, clockId, now) → ms
  view(session, now) → View                                // 渲染所需的一切，见 3.4

  // 动作（都返回新 session；不适用时原样返回并带 session.lastFeedback）
  toggle(session, now)          // 空格
  floor(session, side, now)     // A / L（仅 dual）
  pause(session, now)           // P：暂停 / 继续
  adjust(session, deltaMs, now, clockId?)   // ↑↓，默认调当前 active 或 main
  yieldTime(session, now)       // G G：当前持有发言权的一方放弃剩余时间（仅 dual）
  reset(session, now)           // R R：当前环节恢复初始
  goto(session, index, now)     // 跳到某环节；先暂停并结算当前环节
  next(session, now); prev(session, now)
  insertExtra(session, group, variantIndex, side, now)  // 插在当前环节之后，成为下一个
  undo(session, now)            // Z / Ctrl+Z

  tick(session, now) → { session, events }   // 推进自动规则、产出视觉事件
  upcomingBells(session, now) → [{ at, sound, clock }]   // 供 bells.js 预排
  record(session, now) → [{ index, name, side, type, planned, used, over, yielded }]  // 本场记录
}
```

`session.lastFeedback`：`null` 或 `{ code, message }`，比如 `{code: 'locked', message: '反方时间已用完'}`、`{code: 'extra-limit', message: '正方的奇袭已经用过了'}`。UI 把它显示成 1.5 秒的提示条。每个动作开头清掉它。

### 3.2 动作语义

- **toggle（空格）**
  - `single` / `break`：没在走就开始（`running = true, since = now`），在走就暂停（结算 `used += now - since`）。`break` 已 `done` 时无动作
  - `dual`：`active` 为 null 时把发言权给 `first` 并开始；在走时切给另一方（另一方被锁定则无动作，反馈 `locked`）；暂停中则继续当前一方
  - 光标在开场卡（-1）上：等同 `next`；在结束卡上：无动作
- **floor(side)（A / L）**：只对 `dual`。那一方被锁定则无动作并反馈。否则结算当前 active，`active = side`，开始走。已经是那一方且在走：无动作
- **pause（P）**：在走就暂停，暂停中就继续（`dual` 暂停中且 `active` 为 null 时等同 toggle）
- **adjust（↑ +1 秒，↓ −1 秒，Shift 为 ±5 秒）**：`used -= delta`，`used` 夹在 `[0, total]` 之外的规则：`used ≥ 0`（剩余不超过总时长）；单方允许 `used > total`（超时）。`dual` 被锁定的一方加时后剩余 > 0 则解锁。调整后剩余时间高于某铃点的，那个铃点重新布防（从 `fired` 里移除）。低于铃点且此刻没在走的，静默标为已触发
- **yieldTime（G 连按两次，1.5 秒内）**：只对 `dual` 且有 active。把 active 一方锁定，`yielded[side] = remaining`，`used = total`；另一方未锁定则立刻转给另一方并开始走，否则环节完成
- **reset（R 连按两次）**：当前环节的 Run 删掉重建
- **goto / next / prev**：先暂停并结算当前环节，再移动光标。各环节的 Run 保留，回到之前的环节看到的是它暂停时的状态。光标范围 `[-1, timeline.length]`
- **insertExtra**：只在当前环节已开始过且没在走时允许（"大环节结束后发动"），或光标在两个环节之间也允许。`extrasUsed[group][side] < perSide` 才允许。新环节 `id = 'x-' + 序号`，`extra: true`，`name = (side==='pro'?'正方':'反方') + variant.name`，插入到 `cursor + 1`，光标**不**自动移动（计时员按 → 进入）
- **undo**：动作前把 session（去掉 history）压栈，`undo` 弹出恢复。语义是"那一下没按过"：恢复到按错之前的状态，那之后流逝的时间照常算在当时在走的那个表上。例：自由辩正方在说，计时员误按空格切给反方，3 秒后按 Z，结果是正方一直在走、反方没动。`tick` 和 `upcomingBells` 不压栈
- **自动规则（tick 里执行）**
  - `dual`：active 一方剩余 ≤ 0 时，按**精确的耗尽时刻** `exhaustAt = since + (total - used)` 结算：`used = total`，锁定；另一方未锁定就 `active = 另一方, since = exhaustAt` 继续走；否则 `running = false, done = true`
  - `break`：剩余 ≤ 0 时 `used = total, running = false, done = true`
  - `single`：不自动停，剩余可为负（超时）

### 3.3 铃点事件

每个时钟的有效铃点：`warn` 中每个 t 生成 key `w<t>`（剩余 t 秒）；`countdown` N 生成 `c<N>…c1`；终止 key `end`（剩余 0）。

`tick(session, now)` 对当前环节**在走的**时钟检查：剩余 ≤ 铃点且 key 不在 `fired` 里 → 加入 `fired`，并且若越过铃点的时刻距 now 不超过 1500 毫秒，产出事件 `{type: 'warn'|'count'|'end', clock, key, at}`；超过 1500 毫秒的（比如崩溃后恢复）静默标记，不补响。`dual` 自动转换时一并产出 `{type: 'switch', from, to, at}`。事件只驱动**视觉**效果；声音由 3.5 的预排负责，避免节流导致的延迟。

`break` 的终止事件 type 为 `end`，声音是 `chime`。

### 3.4 View（渲染契约）

`view(session, now)` 返回纯数据，`render.js` 只读它：

```js
{
  mode: 'title' | 'stage' | 'end',
  match, theme, proSeat,
  stage: { index, count, name, type, side, speaker, block, note, extra } | null,
  clocks: [ { id: 'main'|'pro'|'con', side, total, remaining, running, active, locked, yielded,
              fraction /* 剩余/总，夹在 [0,1] */, overtime /* ms ≥ 0 */, phase /* 'calm'|'warn'|'count'|'over'|'done' */ } ],
  running: bool,
  next: { name, type, side, secs } | null,
  progress: [ { index, side, type, block, state: 'done'|'current'|'todo', extra } ],
  extras: [ { group, perSide, used: {pro, con}, variants } ],
  feedback: session.lastFeedback
}
```

`phase`：剩余 > 最大 warn 点 → `calm`；≤ 最大 warn 点 → `warn`；≤ countdown N 秒 → `count`；单方超时 → `over`；锁定或完成 → `done`。

时间显示：剩余 ≥ 0 用 `m:ss`，秒数向上取整（显示 `0:01` 直到真正到 0）；超时显示 `+m:ss`，向下取整。由 `DT.engine.fmt(ms)` 统一格式化。

### 3.5 铃声预排

`upcomingBells(session, now)`：对当前环节**在走的**时钟，列出未触发、在未来的铃点及其绝对时刻 `at = now + (remaining - t*1000)`，外加终止铃。`dual` 还要推演：active 耗尽后若另一方未锁定，另一方的铃点从 `exhaustAt` 起算一并列出。`bells.js` 在每次 session 变化后取消全部已排的声音，用 `AudioContext.currentTime + (at - now)/1000` 重新排。这样即使窗口在后台被节流，铃声也准时。

## 4. 铃声（bells.js）

全部用 WebAudio 当场合成，不带音频文件。

| 声音 | 用途 | 合成 |
|---|---|---|
| `ding` | 提示铃、手动敲铃（B） | 击铃：基频 1318 Hz，泛音比 1 / 2.76 / 5.40，增益 1 / 0.35 / 0.15，起音 3 ms，指数衰减 1.4 s |
| `double` | 终止铃（默认） | 两声 `ding`，间隔 320 ms |
| `triple` | 终止铃 | 三声，间隔 280 ms |
| `long` | 终止铃 | 一声 `ding`，衰减 3 s，基频 1046 Hz |
| `tick` | 逐秒倒数 | 木鱼感短音：1760 Hz 正弦 + 带通噪声，45 ms |
| `chime` | 间隔环节结束 | 两个柔和的音 C6 → G6，各 700 ms |

API：

```js
DT.bells = {
  unlock()                        // 在第一次用户手势里调用，创建 / 恢复 AudioContext
  isUnlocked() → bool
  setVolume(0..1); setMuted(bool)
  play(sound)                     // 立即播放
  schedule(list, now)             // list 来自 engine.upcomingBells；先 cancelAll 再排
  cancelAll()
  _synth                          // 测试用：可注入假的 AudioContext
}
```

`schedule` 按 `sound` 名与 `at` 去重（同一时刻同一声音只排一次）。所有节点挂在一个 master GainNode 上，`cancelAll` 断开并停止已排的节点。没有解锁前，`schedule` 只记下列表，解锁后补排仍在未来的部分。

## 5. 视觉设计

### 5.1 设计立意

计时器在辩论场里的职责只有一个：让全场一眼知道**现在谁在说、还剩多少**。所以视觉的主角不是数字的装饰，而是**发言权本身**：正方说话时整间屋子是朱色，反方说话时是靛色，时间一点点被收回到该方的席位那一侧。数字随时间流逝逐渐收紧变粗。这是本设计唯一的大胆之处，其余一切安静、克制。

### 5.2 默认主题「堂」（hall）色值

| 名 | 值 | 用途 |
|---|---|---|
| 朱 `--pro` | `#B8322A` | 正方色场 |
| 朱·沉 `--pro-deep` | `#521511` | 正方色场被收回后露出的底 |
| 靛 `--con` | `#1D4E89` | 反方色场 |
| 靛·沉 `--con-deep` | `#0C2340` | 反方色场的底 |
| 黛 `--ground` | `#2A2D33` | 间隔环节、开场卡、结束卡的底 |
| 素 `--ink` | `#F4EFE4` | 数字与标题 |
| 金 `--accent` | `#E4B04A` | 提示铃点的标线、铃声波纹、超时 |

不用纯黑也不用 #111 一类的近黑：底色永远是某一方的"沉"色或黛色，投影时仍有色相。

### 5.3 字体（全部是 Windows 自带或可选装，离线可用）

| 角色 | 字体栈 | 说明 |
|---|---|---|
| 数字 | `"Bahnschrift", "DIN Alternate", "Segoe UI", sans-serif` | Bahnschrift 是 Win10/11 自带的可变字体，有字宽（wdth 75–100）与字重（wght 300–700）两个轴。`font-variant-numeric: tabular-nums` |
| 标题（环节名、辩题） | `"Noto Serif SC", "Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", "SimSun", serif` | 宋体系有仪式感；`font-synthesis: none`，没有粗体时不伪造 |
| 界面 | `"Microsoft YaHei UI", "Microsoft YaHei", "DengXian", system-ui, sans-serif` | 操作台、编辑器、开赛页 |

**数字的张力**：计时中数字的 `font-variation-settings` 随剩余比例连续变化：满时 `wght 300, wdth 100`（轻、舒展），到 0 时 `wght 700, wdth 78`（重、收紧）。线性插值，每帧更新。进入超时后固定为 `wght 700, wdth 78`，颜色换成金。

字号：单方环节数字高约 38vh；自由辩发言方 30vh，另一方 15vh；环节名 5.6vh；发言人 2.8vh；顶栏与底栏 2vh。

### 5.4 投影画面版式

**单方环节 / 质询 / 盘问**（正方在左的席位）：

```
┌────────────────────────────────────────────────────────────────┐
│ 新生赛 第 3 场                                        中科大新生辩论赛 │ ← 顶栏，素 60%
│                                                                │
│ 反方四辩质询正方一辩                                              │ ← 环节名，宋体，左对齐
│ 反四 问，正一 答                                                  │ ← 发言人
│                                                                │
│                         1:47                                   │ ← 数字，居中
│                                                                │
│ ████████████████████████████████████░░░░░░░░░░░░░░░░░░░░░░░░░░ │ ← 色场（全屏背景）从右往左收回（反方在右则从左往右）
│ ▮▮▮▮ ▮▮▮▮▮ ▮▮▮▮▮ ▮ ▮▮                下一环节  反方一辩开篇立论  3:00 │ ← 底栏：进度条 + 下一环节
└────────────────────────────────────────────────────────────────┘
```

- **色场**是铺满全屏的背景层，颜色是当前环节 `side` 的颜色，下面是该方的"沉"色。已用时间比例决定色场被收回多少：`clip-path: inset(0 X% 0 0)`（该方在左）或 `inset(0 0 0 X%)`（该方在右），X = 已用比例 × 100。时间被**收回到发言方自己的席位那一侧**。每帧更新
- **提示铃点标线**：色场上在"剩 30 秒"对应的位置画一条 2px 金色竖线，色场收过它之前一直可见，提前告诉全场 30 秒点在哪
- 顶栏左边是场次名，右边是赛制名，都可以为空；不用"·"拼接
- 底栏左边是**进度条**：每个环节一小段，按 `block` 分组（组间留空），段色 = 该环节的方色（`dual` 为半朱半靛，`break` 为黛的浅色），已完成的段不透明度 1，当前段有金色下划线，未开始的 0.35。这是真正的顺序，所以用分段表示是合理的
- 底栏右边：「下一环节　反方一辩开篇立论　3:00」

**自由辩 / 对辩（dual）**：

```
┌──────────────────────────────────────┬─────────────────────────┐
│ 正方  物理学院                          │                 化学院  反方 │
│                                      │                         │
│ 自由辩论                               │                         │
│                                      │                         │
│               2:31                   │          3:12           │
│                                      │                         │
│ ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ │                         │ ← 发言方脚下的地线（金）
└──────────────────────────────────────┴─────────────────────────┘
```

- 屏幕按席位左右分成两半，**发言方那一半加宽到 58%**，切换时分界线以带回弹的曲线滑过去（`grid-template-columns` 过渡 520ms，`cubic-bezier(.34,1.36,.64,1)`）
- 每一半是本方色场，**自上而下收回**（剩余比例 = 色场高度，色场贴底，像水位下降），下面露出本方"沉"色
- 非发言方那一半降低饱和度与亮度（`filter: saturate(.45) brightness(.78)`，过渡 300ms），数字缩到 15vh
- 发言方脚下一条 4px 金色地线
- 被锁定的一方：数字换成「时间到」或「已放弃」，色场全收回
- 还没开始时两半等宽，底部提示「空格开始，先由正方发言」（按 `first`）

**间隔环节（评委打分、中场休息）**：黛色底，居中显示环节名与倒计时（数字 22vh，不做张力变化），下方大字显示**辩题**（正反方表述各一行，左朱右靛的细竖线标记），再下面是「下一环节」。

**开场卡（cursor = -1）**：黛色底。上半部是辩题：正方表述与反方表述分两行，宋体 6vh，行首各有一块本方色的短竖条；下半部是两队队名按席位左右排开，中间一条细线。底部是「空格开始　第一个环节：正方一辩开篇立论　3:00」。

**结束卡**：黛色底，「比赛结束」，下面是本场记录的简表（环节、计划时长、实际用时，超时的用金色标出），投影上也能直接看。

### 5.5 动画

只有一处**编排好的时刻**：**换环节的揭幕**。其余动画都是对计时员操作或铃点的直接回应。

| 时刻 | 动画 | 时长 / 曲线 |
|---|---|---|
| 换环节（→ ←、点列表） | 新环节的色场从该方的席位那一侧**横扫**铺满屏幕；标题、发言人、数字依次从下方 12px 浮入，错开 70ms | 色场 560ms `cubic-bezier(.2,.8,.2,1)`；文字各 420ms |
| 开始 / 继续 | 数字的冒号开始以 1Hz 呼吸（不透明度 1 ↔ 0.55） | 1000ms 循环 |
| 暂停 | 冒号停止呼吸并保持 0.55；数字下方淡入一行「暂停」 | 200ms |
| 提示铃点（30 秒） | 一圈金色波纹从数字中心扩散（圆环描边，缩放 0.6 → 2.4，不透明度 0.9 → 0）；冒号变金 | 1100ms `ease-out` |
| 逐秒倒数 | 数字每秒一次轻弹（缩放 1.07 → 1） | 240ms |
| 终止 | 两圈波纹，间隔 320ms，与终止铃同步；色场最后一截收尽 | 1100ms × 2 |
| 超时 | 数字变金，"+" 号以 0.5Hz 缓慢呼吸 | 持续 |
| 自由辩切换 | 分界线滑动（见上）；数字大小同步过渡；新发言方地线从中间向两边展开 | 520ms |
| 自由辩一方用完 | 该方一圈波纹，然后自动切换动画 | 同上 |
| 反馈提示（如"反方时间已用完"） | 屏幕顶部中央的提示条下滑出现，1.5 秒后收回 | 200ms |

`@media (prefers-reduced-motion: reduce)`：关掉揭幕横扫、波纹、弹跳、呼吸，只保留颜色与数值变化。

色场的逐帧收回不走 CSS transition，由 `requestAnimationFrame` 直接写 CSS 变量 `--used`（0–1）；数字的张力写 `--tension`（0–1）。

### 5.6 主题

主题 = 一个 CSS 文件，全部规则挂在 `[data-theme="<id>"]` 下，文件第一行是元数据注释：

```css
/* @theme id=hall name=堂 desc=全屏色场，适合暗场投影 */
```

`build.py` 读这行生成 `DT.THEMES = [{id, name, desc}]`，编辑器与开赛页的主题下拉框用它。

**变量契约**（每个主题都要定义，`base.css` 给出默认值）：`--pro --pro-deep --con --con-deep --ground --ink --ink-dim --accent --font-digits --font-title --font-ui`。另有可选的 `--backdrop`（任意 `background` 值，比如一张 data URI 图片或渐变，画在色场之下），以及 `.stage-deco` 装饰层（主题可以用 `::before` / `::after` 画背景图案）。**这就是"以后给不同赛制接不同的背景设计"的接口**：写一个新主题 CSS 放进 `themes/`，重跑 `build.py`，编辑器里给赛制选上。

首批三个主题：

- **堂 `hall`**（默认）：5.2 的色值，全屏色场
- **昼 `daylight`**：亮场投影用。底 `#E7E9EC`，字 `#15171B`，正方 `#B3261E`，反方 `#1A4E8F`，金 `#B7791F`。色场不铺满全屏，而是数字后面一条高 34vh 的横带，收回方式相同
- **绿幕 `chroma`**：直播抠像用。底 `#00B140` 纯色，不画色场；数字与标题放在一块本方色的圆角底板上（圆角 2vh），底板宽度随剩余比例收缩；不做背景动画

赛制的 `theme` 是默认值，开赛页可以为这一场另选。

### 5.7 操作台与控制

**单屏模式**（默认）：页面就是投影画面。鼠标移动或按 Tab 时，底部浮出**控制条**，2.5 秒无操作后收起（键盘焦点在控制条内时不收起）：

**双窗口模式**：按 O 打开投影窗口后，本窗口自动切换成**操作台**：

- 环节列表：序号、方色竖条、名称、计划时长、状态（✓ 实际用时 / ● 当前 / 超时的用金色 `+0:07`）。点一行跳过去

- 投影窗口关掉后，本窗口回到单屏模式

**覆盖层**：环节列表抽屉（S，单屏模式下从左侧滑出）、插入奇袭菜单（X）、帮助（H 或 ?）、本场记录（在结束卡上，或按 Shift+S）。Esc 关闭。

### 5.9 开赛页（setup.js）

打开文件后的第一页。黛色底，左边是赛制列表（内置赛制在前，用户赛制在后，每项显示名称与环节数、总时长），右边是这一场的信息：

- 场次名（可空）
- 辩题：正方表述、反方表述
- 正方队名、反方队名（可空，空则显示"正方""反方"）
- 正方坐在：左 / 右（默认左）
- 主题：默认用赛制的主题，可改
- 按钮「开始这一场」→ 进入开场卡；「编辑赛制」→ 编辑器

如果 localStorage 里有没打完的场次，顶部显示一条：「上一场还没打完：<场次名或辩题>，停在第 N 个环节。」两个按钮：「继续」「放弃并新开」。

上次填的队名、辩题、席位记在 `dt.lastMatch.v1`，下次预填。

从开赛页或计时中按 E 打开，是一个从底部升起的全屏面板（打开 / 关闭动画 260ms）。计时中打开时，正在进行的比赛不受影响（用的是开赛时拷贝的赛制）。

- 自动保存到 `localStorage['dt.formats.v1']`，右上角淡入「已保存」
- **导出**：当前赛制存成 `<赛制名>.debate-timer.json`；**导入**：选一个或多个 `.json`，逐个校验，同 id 的问「覆盖还是另存一份」。校验失败给出中文原因和出错位置，例如「第 3 个环节：时长要大于 0 秒」
- **恢复默认**：只对内置赛制，把它换回 `DT.BUILTIN_FORMATS` 里的原样
- 删除内置赛制不允许（按钮置灰）；删除用户赛制要确认

导出文件格式：

```json
{ "kind": "debate-timer-formats", "schema": 1, "formats": [ { …Format… } ] }
```

也接受直接是一个 Format 对象的文件。

### 5.11 投影窗口同步（sync.js）

- 按 O：`window.open(<当前文件 URL 去掉 hash> + '#projector', 'dt-projector', 'popup,width=1280,height=720')`
- 投影窗口只负责渲染：它不持有权威状态，收到什么就画什么，自己用 rAF 按 `now` 推算剩余时间
- 操作台每次 session 变化以及每秒一次心跳，用 `projWin.postMessage({type: 'state', session, settings}, '*')` 推送
- 投影窗口里按下的键转发给操作台（`window.opener.postMessage({type: 'key', code, shiftKey, ctrlKey, repeat}, '*')`），除了 F（全屏在投影窗口本地处理）
- 投影窗口第一次打开时显示提示：「把这个窗口拖到投影屏幕上，按 F 全屏」，收到第一次按键后消失
- 容错：session 也写在 localStorage，投影窗口同时监听 `storage` 事件；操作台刷新后，投影窗口通过 storage 事件继续拿到状态；操作台用 `window.open('', 'dt-projector')` 找回同名窗口的引用
- 声音只由操作台播放

### 5.12 持久化键

| 键 | 内容 |
|---|---|
| `dt.formats.v1` | `{ schema: 1, formats: [...用户赛制与改过的内置赛制...] }` |
| `dt.session.v1` | 当前场次 |
| `dt.settings.v1` | `{ volume, muted }` |
| `dt.lastMatch.v1` | 上次开赛页填的信息 |

所有读写包在 try/catch 里；读到坏数据时丢弃并在控制台警告，不让页面白屏。

### 6.1 赛制库解析

对 `formats/*.md`（跳过 `_` 开头的文件）：

- `name`：第一个 `# 赛制：` 标题后面的文字
- `id`：文件名去掉 `.md`
- 「## 流程总表」下第一张表。列名按表头文字认（`序 / 环节 / 时长 / 计时 / 发言人 / 打分块或段`），不按列号
- 每一行：
  - 去掉单元格里的 `**` 粗体标记
  - `计时` 为 `—` → `break`，`side = null`
  - `时长` 含「各」→ `dual`，`secs` 取其中第一个整数，`first = 'pro'`
  - 其余 → `single`；`side` 取 `环节` 里第一个出现的「正」或「反」（`正方…`→ pro，`反方…`→ con）
  - `speaker` = 发言人列（`—` 则为空）；`block` = 最后一列（`—` 则为空）
  - `note`：`双边计时` → 「双边计时：问答共用这一个表」；`single` 且计时为 `单边计时` → 「单边计时：只计盘问方，对方回答时按 P 暂停」；`dual` → 「A 给正方、L 给反方；一方用完自动转给对方」
  - `序` 为 `—` 且 `计时` 不是 `—` 的行（校赛的奇袭）→ 不进 `stages`，解析成 `extras`：`group` 取环节列粗体文字（「奇袭」），`perSide` 取括号里「每方一次」的数字（一 → 1），`variants` 从时长列「质询 150 秒双边 / 申论 120 秒」按 `/` 切开，每段取「名词 + 数字」：名字加上组名前缀成「奇袭质询」「奇袭申论」，含「双边」的 note 为「双边计时：问答共用这一个表」
- stage `id` = `<formatId>-<序>`；休息行没有序号的用 `<formatId>-b<出现次序>`
- `theme = 'hall'`，`bells` 用内置默认值
- 中文数字（一、两、三……十）转换用一个小函数，不引用技能目录的 `_numerals.py`（计时器要能脱离技能目录独立构建）

表格解析失败（找不到流程总表、列名缺失、时长没有数字）→ 打印文件名与行号，退出 1。

### 6.2 内联

读 `src/index.html`，把 `<link rel="stylesheet" href="…">` 换成 `<style>` 内联、`<script src="…">` 换成内联 `<script>`，顺序照 `ORDER`；在最前面注入 `DT.THEMES`。产物第一行注释写明「由 timer/build.py 生成，改源码请改 timer/src/」和生成用的赛制文件列表。产物里不能出现任何 `src=`、`href=` 指向本地文件或网络（`test_build.py` 检查）。

`--check` 在内存里重建一遍，与磁盘上的两个生成文件逐字节比较。

## 9. 不做的（YAGNI）

- 5 秒保护时间：规则层面的，计时器不强制；以后需要可以作为铃声类型加
- 超时后重复敲铃：惯例是显示超时，评委扣分
- 自定义背景图片上传：主题机制已经留了接口（`--backdrop`），以后按需做
- 打包成 exe：界面代码和现在完全一样，以后可以外面再包一层
- 多语言
